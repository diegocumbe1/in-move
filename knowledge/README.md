# Knowledge Base - In Move

Esta carpeta contiene la base de conocimiento del producto In Move. Su objetivo es centralizar la vision, alcance, requisitos, arquitectura inicial y decisiones del proyecto antes de iniciar desarrollo.

La fuente principal de esta documentacion es `PROPUESTA_IN_MOVE.md`.

## Organizacion

| Documento | Proposito |
|---|---|
| [00_PRODUCT_VISION.md](00_PRODUCT_VISION.md) | Resume la vision del producto, problema, solucion, usuarios y objetivos. |
| [01_REQUIREMENTS.md](01_REQUIREMENTS.md) | Lista los requisitos funcionales y no funcionales organizados por modulo y milestone. |
| [02_MARKET_RESEARCH.md](02_MARKET_RESEARCH.md) | Estructura preparada para investigacion de mercado. |
| [03_SCIENTIFIC_RESEARCH.md](03_SCIENTIFIC_RESEARCH.md) | Estructura preparada para investigacion cientifica y referencias tecnicas. |
| [04_UX_UI_BENCHMARK.md](04_UX_UI_BENCHMARK.md) | Estructura para referencias visuales, flujos, componentes y patrones UX. |
| [05_BRANDING.md](05_BRANDING.md) | Propuesta inicial de personalidad, tono, valores e identidad visual. |
| [06_DESIGN_SYSTEM.md](06_DESIGN_SYSTEM.md) | Estructura para definir tokens, componentes, responsive y accesibilidad. |
| [07_MVP_SCOPE.md](07_MVP_SCOPE.md) | Define el alcance del MVP: M0, M1, exclusiones, criterios y entregables. |
| [08_DATABASE_MODEL.md](08_DATABASE_MODEL.md) | Documenta funcionalmente entidades, relaciones, catalogos y datos principales. |
| [09_TECH_ARCHITECTURE.md](09_TECH_ARCHITECTURE.md) | Describe la arquitectura tecnica inicial basada en la propuesta. |
| [10_ROADMAP.md](10_ROADMAP.md) | Organiza el roadmap por fases y milestones M0-M5. |
| [11_DECISIONS_LOG.md](11_DECISIONS_LOG.md) | Registro vivo de decisiones importantes del proyecto. |

## Principios de mantenimiento

- No agregar funcionalidades sin trazabilidad a la propuesta o a una decision registrada.
- Marcar como `Pendiente por definir` cualquier informacion no confirmada.
- Registrar decisiones relevantes en [11_DECISIONS_LOG.md](11_DECISIONS_LOG.md).
- Actualizar [07_MVP_SCOPE.md](07_MVP_SCOPE.md) y [10_ROADMAP.md](10_ROADMAP.md) cuando cambie el alcance.
- Mantener alineados requisitos, arquitectura y modelo de datos.

## Estado actual

La documentacion representa una base inicial para discovery y planificacion. No reemplaza la validacion con el cliente sobre campos exactos, escalas oficiales, roles, requisitos legales, marca, dominio, hosting y volumen esperado.
